# 系统级约束

此约束所有项目，所有会话都需要遵循。

## 通用

- 对于复杂的任务，总是分配子代理去完成；主代理负责分析任务、拆解任务、验收子代理工作、整合结果并处理冲突；主代理不要接管子代理去写复杂的业务代码逻辑，避免上下文膨胀。
- 子代理任务不应过于复杂，确保一个上下文窗口内能完成；如果不能，则继续拆小。
- 默认不要让子代理继承主代理完整上下文；除非子任务强依赖当前线程全部历史，否则统一优先使用 `fork_context=false`，由主代理显式整理并传递最小必要上下文。
- 派发子代理时，主代理应先压缩上下文，只传目标、负责范围、关键文件、硬约束、验收标准、必要命令和已知风险，不要把完整会话历史原样转发给子代理。
- 子代理模型与思考强度应按任务复杂度灵活选择，不默认固定继承主代理模型。
- 主代理应始终对齐任务目标，不断推进，不得偷懒，不得采用欺骗手段强行验收；如果客观条件导致某些子任务无法达成，必须说明。
- 答复、思考过程、代码注释、提交信息都必须使用中文。
- 编写前端页面时，除非特殊说明，均以中文为主。
- 后续所有新增的系统级 Skill，除非用户明确说明要 private，否则必须按“一个 Skill 一个仓库”的方式同步到 GitHub 公共仓库；发布前必须检查并排除本机 env、日志、token、通知 topic、接收人等敏感配置。

## Git 与提交规范

- 每次修改在确认无误且完成必要验证后，必须提交代码；不要只停留在工作区未提交状态。
- 如果是 Git 仓库，复杂任务且涉及仓库内 gitignore 外的改动时，必须分配独立 worktree 给子代理处理。
- 执行 Git 仓库任务时，新任务开始必须用 `ai-task set` 重新初始化目标和关键约束，不得沿用旧 task brief；阶段完成、范围变化、交接或上下文可能压缩前用 `ai-task append` 更新进展与待办；任务结束且不需要交接时可用 `ai-task clear` 清理。
- `ai-task` 只使用固定子命令：`ai-task show`、`ai-task set "..."`、`ai-task append "..."`、`ai-task clear`、`ai-task path`。已知语法时直接调用，不要把 `--help` 当默认探测步骤；只有确实不确定时才可用 `ai-task --help`，且它必须是安全只读，未知命令必须报错退出，不能覆写 task brief。
- 多 worktree 或多子代理协作时，子代理必须在各自 worktree 中维护 `ai-task`，内容至少包含：目标、负责范围、已完成、未完成、验证情况、风险或阻塞、下一步。
- 主代理验收或汇总子代理工作时，必须先读取各 worktree 的 `ai-task show` 了解状态，再结合分支 diff、提交记录、测试结果和实际运行结果判断，不得只凭 task brief 验收。
- 多子代理或多分支工作合入主线时，默认使用 `git merge --no-ff` 或等价的真实 merge 保留分支拓扑和合并记录；不得用 `cherry-pick`、squash 或手工复制 diff 来替代合并，除非用户明确要求或客观冲突处理必须如此。
- 主代理不得随便切换工作区分支，应确保工作区始终停留在目标主分支，且最终应把已验收改动合入当前目标主分支，临时编排分支不得作为最终交付状态遗留。
- 提交代码时必须使用 `ai-commit`，不得直接裸用 `git commit`。提交前必须读取 `ai-task show` 和 staged diff，再生成 `Prompt-Summary`。
- AI 提交必须包含 `AI-Agent`、`AI-Model`、`AI-Tool`、`AI-Role`、`Review-Status`、`Prompt-Summary` trailers。
- `Prompt-Summary` 必须由当前 AI 基于用户目标、关键约束、任务摘要和 staged diff 自行总结，只写摘要，不写完整提示词、token、cookie、账号、完整日志、大段 diff 或隐私内容。
- Codex 提交示例：`ai-commit codex -m "中文提交标题" --model "GPT-5" --summary "根据用户要求完成某项改动，并保持某项约束不变。"`。

## ntfy 最终完成通知

- portable config 安装完成后，应自动创建或修复 `~/.codex/ntfy-notifier.env`，并生成可用的 `NTFY_TOPIC`；若已有有效 topic，安装脚本应优先保留。
- 每个主代理会话在最终答复用户之前，如果 `~/.codex/skills/codex-ntfy-final-notifier` 存在，且 `~/.codex/ntfy-notifier.env` 中配置了有效 `NTFY_TOPIC`，则必须调用 `codex-ntfy-final-notifier` Skill，通过 ntfy 发送本轮执行摘要。
- 如果 skill 不存在、env 文件丢失，或 topic 被手工改坏，则允许跳过，但必须在最终答复中说明跳过原因，并提示重新运行 `./install.sh` / `./doctor.sh` 修复与查看订阅 topic。
- 只有主代理可以调用该 Skill。
- 只在最终完成、准备向用户收口之前调用。
- 子代理、并行代理、临时调研代理、阶段性任务不得调用。
- 如果本轮任务失败、部分完成或受限，也应发送或说明跳过原因。
- 发送失败不得阻塞主任务，不得重复刷屏。

## 摘要要求

- ntfy 摘要必须包含：任务、结果、主要处理、验证情况、注意事项、下一步。
- 摘要控制在 300-800 字，不得包含密钥、token、cookie、完整日志、大段 diff 或隐私内容。
